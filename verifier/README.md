# Course verifier (Node, no deps)
Extracts the code between `// ==PHYSICS START==` and `// ==PHYSICS END==` from index.html and runs it headless.
- `node sim.js path/to/index.html` : simulated players (reaction delay 10-300ms, random finger lifts, with/without checkpoints) at air accel 150/400/800. Reports finish rate, falls, time.
- `node extra.js path/to/index.html` : baselines (no input, hold-without-steering) and sloppy players (300-500ms, 30-50% lifts).
Bot obeys real touch rules: on ramp, held finger auto-pushes into ramp and swipes only steer; in air, strafe = last swipe direction and you can only turn that way; turn rate capped at 3 rad/s.
Last results (v6): good bot ~65-70s, sloppy ~79s, very sloppy ~114s, all finish with checkpoints; hold-only fails at first turn.
v7 (soft drag removed; uphill ramp before each checkpoint, net climb 350): good bot ~70-77s (10ms bot fails at ramp 11->12, pre-existing, baseline 100ms bot fails there too), vmax 2187 (drag v6: 2113), noisy clean 22-24/30 (v6: 4/30), sloppy ~83s, very sloppy ~108-123s, all finish with checkpoints, no respawn soft-locks; hold-only fails at first turn.
v8 (checkpoints every 12 ramps instead of 4; physics unchanged): checkpoints reached at ~32s and ~58s (good bot), finish 70.7s. Clean runs unchanged. Penalty per fall rises: sloppy 500ms/40% lifts 123s -> 135s, 50% lifts 108s -> 113s. All finish, no respawn soft-locks.
v9 (auto-push always on during ramp contact; finger only matters in air): good bot identical (70.7s). Noisy clean 25/30 (v8: 24/30). Sloppy 40% lifts 1.1 falls/135s->121s, 50% lifts 1.5 falls/113s->127s (n=20, within noise). Lifting on a ramp was never useful: with no push you slide off the face in ~2.4s, and heading does nothing without strafe.
v10 (hand-built STAGE list replaces procedural course; 39 ramps, 2 checkpoints): good bot 70.9s, splits 26.7/23.7/20.5s; 300ms bot 91.8s. Strafe gap (ramp 18, gap 1350, drop 320) is a hard air-control check: bots with air control pass, no-air bot 0/10, sloppy 30-50%-lift bots finish 3-9/20 (falls cluster at ramp 17). Gap 1100 = nobody needs air control; 1250-1450 is a knife edge.
v11 (base ramp half-width 400 -> 460; finale slalom still 370 -> 310): good bot 71.9s (v10 70.9), 300ms bot 80.3s (v10 91.8), sloppy 30%-lift finishes 17/20 (v10 9/20). Strafe gap still a gate (no-air 0/10). Tested: uniform 1.15x similar; 1.3x slows the good bot; 500 or 1.5x makes the strafe gap passable without air control.
v12 (levels: STAGES[1] cruise, STAGES[2] = v11 stage; select with globalThis.SURF_LEVEL, e.g. node -r ./lvl.js sim.js with lvl.js setting it; fail line now also uses the next ramp's base so big drops aren't falls): Level 1 good bot 72.1s, splits 27.1/25.9/19.1s, 300ms bot 76.6s, all sloppy bots finish 20/20 with ~0 falls, no air control needed. Level 2 unchanged (71.9s).
v13 (refactor only, physics unchanged): sim state (pos, vel, yaw, contact, strafe, squash, cmd) now lives inside the PHYSICS block; input enters only through `cmd {turn, touch, key}`, consumed once per tick. sim.js, extra.js and tools/* load the block through verifier/harness.js (no more pasted wrappers). Results identical to v12: L1 good bot 72.1s, L2 71.9s; air-strafe gain 71/44/30/22; L2 splits 26.3/23.4/22.2.
Golden replays (verifier/golden.js): `node verifier/golden.js check index.html` replays the stored good-bot cmd streams (verifier/golden/L1.json, L2.json, 400 air accel) and compares a trace digest every 100 ticks. Run after ANY physics or stage change; if the change is intended, `record` and commit the new files with a README line explaining why. Verified to fail on a 0.1% gravity change.
v14 (physics rule fix, replays unchanged): the finish pad can no longer splat. If the player is over the pad footprint and above fin.y - 150 the fall check is skipped. Before, touching a ramp other than the last one put the fail line (900 below the lower of last-touched/next ramp bases) ABOVE the pad, so every pad spot splatted. L1/L2 results and golden replays identical.
